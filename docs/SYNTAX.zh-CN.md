# vemry Markdown 方言

vault 的唯一真源是磁盘上的纯 Markdown 文件。本文定义 vemry 在 **CommonMark + GFM** 之上额外识别的全部记号，以及每一条在**不认识它的标准 Markdown 渲染器**里的降级形态。

这份文档同时是 [CONTRIBUTING.md](../CONTRIBUTING.md) 「零锁定」原则的评审判据：新语法必须先进入本文，并在这里写明降级行为——判据见文末[「新增语法的门槛」](#新增语法的门槛)。

> English: [SYNTAX.md](SYNTAX.md)。本文是它的中文版，两份逐节对应，改动请同步。

实现真源：`crates/vemry-core/src/parser.rs`（块级扫描器，行级 + 内联，刻意不用完整 Markdown AST）、`crates/vemry-core/src/note.rs`（frontmatter）、`src/lib/editor/`（渲染侧）。

## 基线

CommonMark + GFM（表格、删除线、任务列表）+ 文首 YAML frontmatter。凡本文未列出的记号，vemry 一律按标准 Markdown 处理，不做额外解释。

方言里的每个关键词都是英文，不随界面语言变，日期一律 ISO：`every 2 weeks`、`when done`、
`3d2h15m`、callout 类型名、`/` 命令。它们靠记忆盲打，也要被别的机器读，所以一篇笔记在日文
和德文的机器上是同一个文件，一条命令只有一种拼法。选择器和补全会翻译，插入的内容不会。

## Frontmatter

```yaml
---
title: 可选标题
tags: [研究, 睡眠]        # 也接受单个字符串
aliases: [别名一, 别名二]  # 参与 wikilink 的裸名解析
created: 2026-08-20
private: true             # 进隐私区：对 AI 永远不可见
vemry:                    # vemry 自己写的溯源信息，与用户字段隔离
  origin: agent           # agent | capture
  agent_session: <id>       # 创建这篇笔记的研究会话（.vemry/sessions/<id>.jsonl）
---
```

未知字段原样保留（`Frontmatter.extra` 展平透传），往返读写不会吃掉你自己的元数据。块级出处（谁写了哪一块）不是语法：它记在 `.vemry/provenance.jsonl` 里，正文没有任何标记。

**降级**：标准 YAML frontmatter，绝大多数 Markdown 工具原生识别；不识别的渲染器把它显示为顶部一段 `---` 包裹的文本，正文完整。

## 链接与嵌入

| 写法 | 含义 |
|---|---|
| `[[目标]]` | 指向笔记 |
| `[[目标\|别名]]` | 显示别名 |
| `[[笔记#小节]]` | 指向标题 |
| `[[笔记#^块ID]]` | 指向块 |
| `[[#小节]]` / `[[#^块ID]]` | 目标为空 = 本篇自身 |
| `![[图片.png]]` | 内联嵌入图片 |
| `![[图片.png\|300]]` | 指定显示宽度（px） |
| `![[笔记]]` | 嵌入整篇笔记（正文，只读） |
| `![[笔记#小节]]` | 嵌入一个小节 |
| `![[笔记#^块ID]]` | 嵌入一个块（列表项带上子项） |

解析规则（`scan_inline`）：`[[…]]` 不跨行、内容非空，行内代码 `` ` `` 之间不解析。

目标解析（`BlockIndex::resolve_target`）：目标为空 = 本篇；含 `/` 按完整相对路径匹配；裸名匹配文件名主干或 `aliases`，**大小写不敏感**，歧义时路径最短者胜。

**降级**：显示为字面文本 `[[目标]]`——可读，但不是链接。**这是本方言里降级最弱的一条**：语义（链接图、反向链接）在外部工具中丢失，文本不丢。

**嵌入**（目标不是图片的 `![[…]]`）在编辑器里显示目标当前的文本——实时、只读的投影，不复制任何内容进本文件。独占一行时是一个带标题行的块，点标题行跳到来源；在行中时是一枚胶囊。嵌入只展开一层：嵌入内容里的 `![[…]]` 显示为 ⧉ 链接，因此嵌入结构上不可能循环；嵌入本篇自身（或所在小节）显示一个标记。目标解析不到时保留原文并显示「未找到」。agent 读笔记时看到的是字面 `![[…]]`，永远不是被嵌入的内容（原因见「隐私标记」）。降级：字面文本。

## 标签

行内 `#标签`，与 frontmatter `tags` 合并去重。

- 允许的字符：字母、数字、`_`、`-`、`/`（支持 `#研究/睡眠` 层级）
- 前一个字符不能是字母、数字、`#` 或 `&`（避开 `&#8203;` 一类实体）
- 纯数字不算标签（`#1` 是普通文本，不是标签）
- 行内代码之间不解析
- 编辑器把标签画成胶囊，`#` 保留但调淡（井号是让这个词在磁盘上成为标签的字符）；投影里的标签 chip 同样如此

**降级**：普通文本。行首的 `#标签` 不会被误当成标题——ATX 标题要求 `#` 后必须有空格，vemry 与 CommonMark 在这点上一致。

## 任务

```markdown
- [ ] 待办
- [/] 进行中
- [x] 已完成 ✅ 2026-08-21
- [-] 已取消 ❌ 2026-08-21
- [ ] 带日期的任务 ⏩ 2026-08-10 ⏳ 2026-08-15 📅 2026-08-20
- [ ] 等价的 ASCII 写法 [start:: 2026-08-10] [scheduled:: 2026-08-15] [due:: 2026-08-20]
- [ ] 其余属性 ❗ 🔁 every week 🕐 45m 🆔 scan01 ⛔ k3x9pa 🚮
```

- 列表符 `-`、`*`、`+` 均可，任意缩进
- `[?]` 中方括号后必须是空格或行尾
- `x`/`X` 都算完成，`-` 是取消；未知状态字符按待办处理
- 复选框是状态的唯一真相，✅ / ❌ 日期只记录时间。勾选写入 `✅ 今天`，`[-]` 写入
  `❌ 今天`，重新打开则去掉戳记——编辑器、日程、看板和 agent 一律如此
- 文字之后的每个属性都有 emoji 与方括号 `[key:: value]` 两种写法，读出的结果相同：

| 属性 | Emoji | `key::` | 值 |
|---|---|---|---|
| 截止日期 | `📅` | `due::` | `YYYY-MM-DD` |
| 排期日期——打算做的那天 | `⏳` | `scheduled::` | `YYYY-MM-DD` |
| 开始日期——最早可开始 | `⏩` | `start::` | `YYYY-MM-DD` |
| 创建日期 | `➕` | `created::` | `YYYY-MM-DD` |
| 完成日期 | `✅` | `completion::` | `YYYY-MM-DD` |
| 取消日期 | `❌` | `cancelled::` | `YYYY-MM-DD` |
| 优先级 | `❗❗` `❗` · `❕` `❕❕` | `priority::` | `highest` `high` `low` `lowest` |
| 重复 | `🔁` | `repeat::` | `every [N] day\|week\|month\|year [when done]` |
| 完成即弃 | `🚮` | `onCompletion::` | `delete` |
| 编号 | `🆔` | `id::` | 一个词 |
| 受阻于 | `⛔` | `dependsOn::` | 编号列表，逗号分隔 |
| 估时 | `🕐` | `estimate::` | `30m` `2h` `1d`（一天按 8 小时计） |

- 属性是行尾的那一串，从行尾向前读：属性、`#标签`、`[key:: value]` 字段和 `^anchor`
  都让这一串继续，遇到第一个都不是的词就停——前面整段是正文，正文里的 `📅` 只是一个
  词。同一属性在这一串里出现两次，以最后一个为准。裸的 `key:: value` 是普通字段，不是
  属性
- 日期只认 `YYYY-MM-DD`。标记后面不是日期的一律当普通文字：`⏳ 等回复` 对解析器什么
  都不是（写在行尾时，这一串也到此为止）。emoji 后的空格可有可无，紧贴在前一个词后面
  的 emoji（`写周报📅 2026-09-15`）照样是属性；`[key:: value]` 在方括号处结束
- vemry 自己新写入的属性按这个顺序落位，锚点永远在最后：
  `🆔 ⛔ ❗ 🔁 🚮 🕐 ➕ ⏩ ⏳ 📅 ❌ ✅ ^id`——从菜单设的日期落在自己的位置上，已有的原地
  改写，两种拼法都一样。从视图新建的任务（看板的快速新建）带 `➕ 今天`，手写的行可以
  省略
- 怎么输入：在任务行上打 `@` 会列出全部属性——`@due`（以及 `@scheduled`、`@start`）
  插入标记并弹出日期菜单，`@urgent` … `@someday` 是优先级，`@every week` 是重复规则，
  `@estimate 2h`、`@removed once done`，`@id` 生成一个新编号，`@depends on` 插入
  `⛔` 等你粘贴编号；`@today` 等日期插入截止日期。在 `[priority::`、`[repeat::`、
  `[estimate::` 之后，补全会列出可选的值。没有一个 emoji 需要手打
- 优先级：一个 `❗` 是重要，两个是紧急；一个 `❕` 是以后，两个是有空再说；不写就是普通。
  同一行不混用两种
- 重复：勾选时把下一次写在本行上方，所有日期整体平移一个周期——以截止日期为准，没有
  则用排期或开始日期；带 `when done` 时从勾选当天起算。新行重新打开、去掉戳记和
  `^anchor`，并刷新 `➕`。规则文字一直到下一个属性、字段、标签或锚点为止，所以多个词的
  规则用 `key::` 写法时要带方括号
- `🚮`：勾选即删行；有重复时，由下一次占它的位置
- 受阻于：列出的编号只要有一个属于未关闭的任务，本任务就受阻——日程把它灰显并标出在
  等谁。编号是任务自己的，不是块 ID：`^anchor` 指向块，`🆔` 指向任务。编号在被需要时
  才产生：任务菜单（日程、看板）里的「复制任务编号」生成六位 `[a-z0-9]`，写进该行并
  复制，接着就能粘到 `⛔` 后面
- 其它工具写的拼法也能读，编辑该行时原地改写：`🛫` 读作开始日期，`⌛` 读作排期，
  `🔺 ⏫ 🔼 🔽 ⏬` 读作优先级，`🏁` 读作完成即弃，`priority:: medium` 读作 high。
  vemry 自己只写第一种拼法
- 编辑器把复选框画成复选框（`[/]` 画成半选的短横，`[-]` 画成打叉）：单击切换完成，
  ⌥ 单击切换进行中——查询行的复选框也是这两个手势。各属性画成标签片，各有各的色调：
  开始日期和完成戳记用通行色，排期用强调色，有压力的——紧急、仍锁着的依赖、逾期的截止
  ——用警示色，其余灰色。光标触到的属性显示原文以便编辑——emoji 本身画成图标加属性名
  （`due`、`repeat`、`priority high`），后面的值是普通文字。本身就是一个整体的标记——
  优先级、`🚮`、还没填值的标记（弹着日期菜单的 `📅`）——光标在它上面或紧跟其后的空格
  之后时显示为这个原子，光标在别处时只画图标，在它后面按一次 Backspace 整个删掉。
  解析器没读的东西在每一行都有下划线，原因在提示里：写坏的日期、
  落在正文而不是行尾那一串里的属性、同类属性中靠前的那个。文件里的 emoji 拼法从不上屏

**降级**：`[ ]`/`[x]` 是标准 GFM 任务列表，直接就是复选框；`[/]`、`[-]` 不是 GFM 的
任务标记（GFM 只认空格与 `x`/`X`），退化为普通列表项加字面文本，仍然可读；属性是行内
纯文本。emoji 与 `key::` 的拼法与 Obsidian 的 Tasks 插件相同（这是互操作事实，不是
借用的设计）：同一个知识库两边打开读到同样的日期，`⏩`、`❗ ❕`、`🚮`、`🕐` 在那边只是
普通文字。

## 列表

```markdown
- 一项
  比标记缩进更深的续行归这一项
  - 嵌套项是独立的块
1. 有序列表同样
2) `.` 与 `)` 都可以
```

每个列表项都是独立的块——标记行加上比标记缩进更深的续行。任意深度的新标记都开启下一个块，所以嵌套项是另一个块，**挂在某一项上的 id 只覆盖那一项，不含子项**（引用或嵌入该项时会连带显示子项）。空行、标题、围栏、callout 或复选框项都结束这一项。不缩进的懒续行不识别，会成为段落。`- - -` 与 `* * *` 是分割线，不是列表项。

- 标记：`-`、`*`、`+`，或一到九位数字后接 `.` 或 `)`，再接一个空格；任意缩进（一个 tab 算一格）
- 索引记录缩进量与是否有序
- 复选框项是[任务](#任务)不是列表项；`1. [ ] x` 是列表项
- 表格、普通引用、分割线仍按段落索引
- 无序列表与有序列表之间要留空行。CommonMark 规定编号不是 `1.` 的有序标记不能打断段落，所以紧贴在无序项文字下面的 `2. x`，在标准渲染器和编辑器的块模型里都是那一项的懒续行，而索引（不识别懒续行）会把它读成一项。编辑器的块移动与拖放总是在两种列表之间补空行

**降级**：标准 Markdown 列表。这是索引粒度，不是语法——写法没有任何不同。

## 内联字段

```markdown
author:: Ursula K. Le Guin
- 再读一遍 [rating:: 5] [status:: done]
- [ ] 写规格 due::2026-08-10 #work
> status:: reading
```

字段就是 `key:: value`。键由字母、数字、`_`、`-` 组成（中文键可用：`作者:: 勒古恩`），不能全是数字；`::` 后必须是空白、数字或行尾——所以 `std::vector`、`C++::foo`、`12::30`、`http://x` 都不是字段。三种形式：

| 形式 | 位置 | 值 |
|---|---|---|
| 整行 `key:: value` | 块前缀（缩进、`>`、列表标记、复选框）之后 | 该行余下部分，去掉行尾 ` ^id` |
| `[key:: value]` / `(key:: value)` | 行内任意位置，不嵌套、不跨行 | 到配对的括号为止 |
| 行中 `key:: token` | 前一个字符是空白 | 一个 token，到下一个空白为止 |

- 每个块记录自己的字段（键、原样的值、位置）；值由读它的人解释——日期、数字、`[[链接]]`、`a, b` 列表——解析器不解释
- 任务行上带方括号的 `[due:: …]` / `[scheduled:: …]` 既是任务日期也是普通字段；裸的 `due:: …` 只是字段；emoji 写法（`📅` / `⏳` / `⏩` …）只是任务属性
- 行内代码、`[[wikilink]]`、围栏代码与 frontmatter 内不扫描
- frontmatter 的标量（以及 `created`）是笔记级字段：块没有该键时字段过滤会回退到它们（`title`、`tags`、`aliases`、`private`、`vemry` 是元数据，不算字段）
- 空值（`[key:: ]` 或 `[key::]`：块类型留下的占位，或没打值就闭合的括号）对索引而言不是字段；编辑器把它显示为一个待填的空 chip；日期键的 `key:: ` 补全里有「选一个日期…」，回车即在光标处弹出日期菜单，手动打出闭合空字段的 `]` 也会立刻弹出它的菜单
- 编辑器里字段渲染为 chip；点击弹出取值菜单——自由输入框、知识库里已用过的值、「移除字段」；日期值改弹日期菜单；状态字段的 chip（块类型里 `type: state` 的键，见「块类型」）带着它那一档的图形，菜单按顺序列出各档

**降级**：`key:: value` 是可读的纯文本；`[key:: value]` 显示为方括号文本（没有 `(url)`，不是链接）；`(key:: value)` 是括号文本。不会吞掉内容，也不会打断列表。

## Callout 与断言/证据

```markdown
> [!warning] 可选标题
> 后续以 > 开头的行都并入这个 callout

> [!claim] 睡眠影响记忆巩固 ^c1

> [!evidence] Walker 2017 的实验数据
> supports:[[睡眠研究#^c1]], [[另一笔记#^c9]]
```

- `[!类型]` 大小写不敏感、类型内不能有空白；后面可跟 `+`/`-` 折叠记号——编辑器里 `-` 打开时默认折叠，`+` 或不写则展开；折叠状态永远不写回文件
- 识别的类型：`note`/`info`/`todo`/`abstract`/`summary`/`tldr`、`tip`/`hint`/`important`、`success`/`check`/`done`、`question`/`help`/`faq`、`warning`/`caution`/`attention`、`danger`/`error`/`failure`/`fail`/`missing`/`bug`、`example`、`quote`/`cite`、`card`，以及 vemry 自有的 `claim`/`decision`/`evidence`
- 不写标题时显示类型名在界面语言里的译名（中文界面下 `[!warning]` 显示为「警告」）；文件里只保留类型
- `claim`、`evidence`、`private` 进块索引成为独立块类型；`decision` 按 claim 索引（决策就是关于「做什么」的断言：evidence 同样用 `supports:` 支撑它，断言视图也列出它）；其余按段落索引
- `card` 对解析器而言就是「其余」之一（段落），带 `#card` 标签时对复习视图而言是一张卡片：首行是问题，下面的引用行是答案，排程字段（`due` / `interval` / `ease` / `reviews`）落在最后一行——评分就地改写这些字段，笔记本身就是卡组
- `private` 是块级隐私区（见[隐私标记](#隐私标记)）：必须从行首（缩进之后）开始，所以在列表项里要另起一个续行；不带 `>` 的懒续行不在块内
- `evidence` 用 `supports:` 声明它支撑哪些断言：**写了 `supports:` 就只取其后的链接**，没写则整块的链接都算

**降级**：标准 blockquote，`[!warning]` 作为首行文字照常可见。这是本方言里降级最干净的一条。

## 块 ID

行尾 ` ^id`（空格 + `^` + 标识符）给该块一个稳定锚点，供 `[[笔记#^id]]` 引用。没有显式 ID 的块由索引按序号自动分配临时 ID，**不写回磁盘**。

- 标识符字符：`A–Z`、`a–z`、`0–9`、`-`（不含 `_`、不含空格，必须直到行尾）
- 它位于块的最后一行：段落或列表项的末尾、标题的标题文字之后（`# 标题 ^h1`——id 不算标题的一部分，`[[笔记#标题]]` 照常解析）、callout 的最后一个 `>` 行。表格行与围栏代码块不能挂（会破坏结构）。
- **铸造**：只有当你引用、嵌入或复制某个还没有 id 的块的链接时，vemry 才写入 id，且只写那一块——六个来自 `a–z0–9` 的随机字符，笔记内唯一。绝不主动写入；临时 ID 永不落盘。
- 挂在列表项上的 id 只指那一项；子项不属于该 id 的块，但引用该项时会一并显示子项。

**临时的位置引用。** AI 回答可以用 `[[路径#bN]]` 引用一个还没有 id 的块，`bN` 是工具结果里索引的位置 id。这种形式**不属于方言**：只在那一次对话内有效，vemry 永远不会把它写进笔记。回答被复制、插入、送到钉住位置或存为笔记时，每个 `[[路径#bN]]` 都会被物化——被引用的块获得一个铸造的 ` ^id`，链接变成 `[[路径#^id]]`（标题不能挂 id，按标题文字链接为 `[[路径#标题]]`）；无法定位的引用（块已不存在，或是表格、代码块）退化为 `[[路径]]`。

**降级**：行尾的普通文本。

## 行内高亮

`==高亮文字==`。CommonMark 与 GFM 都没有这条；实现是仿 `@lezer/markdown` 自带删除线写法的成对定界符扩展。

**降级**：字面 `==高亮文字==`，可读。

## 公式

| 语法 | 含义 |
|---|---|
| `$E = mc^2$` | 行内公式 |
| `$$\sum_i a_i$$` | 单行的展示公式 |
| 各占一行的 `$$` … `$$` | 展示公式块，公式可跨多行 |

公式由本地 KaTeX 排版（`trust: false`，`\href` 之类被拒；语法错误以红色显示源码而不是弄坏笔记）。编辑器显示排版结果，光标落在上面时显示源码——行内公式按元素揭示，展示块整块揭示；嵌入、阅读投影与聊天面板用同一套文法排版（`src/lib/math.ts` 是唯一定义）。

行内 `$` 只在两端都不是空白、闭合 `$` 后面不是数字时才算公式：`$5 and $10` 是钱不是数学。代码里的 `$` 是代码。`$$` 开头 80 行内没有闭合的展示块保持为文本。

**降级**：字面 `$…$`，多数渲染器要么排版要么原样显示。

## 块类型

`.vemry/types/<名称>.md` 声明一种常写的块：frontmatter 里 `name`、`description`、`kind`（转换目标：`paragraph`、`bullet`、`task`、`quote`、`callout` 等）、`tag`、`icon`、`fields`（键列表，或 `{key, default, values, type}` 映射），正文是模板（`{{key}}` = 字段默认值，`{{date}}` = 今天，`{{cursor}}` = 光标落点）。`/` 菜单与「转换为 ›」列出启用的类型；应用一个类型 = 把块转成该 kind，并把缺失的字段以 `[key:: value]` 连同标签补到行尾。字段的 `values` 是它的 chip 菜单与 `key:: ` 补全优先给出的候选；`type: number` 让菜单的输入框变成数字输入，`type: date` 让 chip 改弹日期菜单。类型化的块就是带行内字段的普通 Markdown——笔记里没有任何东西指向类型，删除类型文件不改任何笔记。agent 的系统提示会列出类型，使它以同样方式写这类块。

`type: state` 把一个字段声明为**状态字段**：它的 `values` 按书写顺序就是一段进程的各档——第一个值是块的起点，最后一个值是终点。这个值出现在哪里，就带着它那一档的图形（空框、自下而上填充的框、打勾的框：与任务 todo / doing / done 画的是同三种形状，所以任务就是一个词表固定为三值、语法固定为复选框的状态字段），chip 的菜单按顺序列出各档，第一项是「推进到 …」。查询块按该字段 `sort` 或 `group`、看板按它分组时，都遵循声明顺序——声明过的每个值都是一组或一列，空的也在。词表之外的值是普通 chip，排在有名的值之后。一个块可以同时带复选框和状态字段（`kind: task` 的类型加一个 `status`）：复选框回答这件事做完没有，字段回答它处在哪一阶段，两者互不联动。

```yaml
fields:
  - key: status
    type: state
    values: [unread, reading, retold, done]
    default: unread
```

**降级**：类型化的块就是带 `[key:: value]` 文本的普通块；状态字段与其他字段一样是一个 `[key:: value]`。

## 查询块

````markdown
```vemry-query
kind: task
task_state: todo
due_before: today
limit: 20
```
````

YAML 体，查询本身是**八个平铺标量**，全部可选（`field` 可重复），另加两个展示键：

| 字段 | 取值 |
|---|---|
| `kind` | `paragraph` / `heading` / `list_item` / `task` / `claim` / `evidence` / `code_block` / `private`（最后一个只供查询块、视图与脚本使用：agent 永远看不到私密块） |
| `note` | 一篇笔记的准确相对路径，如 `projects/Alpha.md` |
| `tag` | 标签名（前导 `#` 会被去掉） |
| `text` | 正文子串 |
| `task_state` | `todo` / `doing` / `done` / `cancelled` |
| `due_before` | `YYYY-MM-DD` 或 `today`（按本地时区求值） |
| `field` | `key`（存在）/ `key = v` / `key != v` / `key < v` / `key > v` / `key ~ 文本`；日期与数字按其类型比较；多行 `field` 须同时成立 |
| `limit` | 正整数 |
| `group` | `note` / `kind` / 一个字段名——每个取值一个可折叠分组，没有该字段的块归到「无」并排最后（只管展示：在编辑器里施加，不属于 agent 工具接受的查询） |
| `sort` | `note` / `kind` / `text` / 一个字段名，可后接 `asc`（默认）或 `desc`；日期与数字按其类型排序，没有该字段的块无论方向都排最后（同 `group`，只管展示） |

不嵌套、不支持表达式——刻意做成一个安全子集：查询本身只读、不能写盘、不能取网络。

每一行结果把块显示成一行，而不是它的源码：左边是任务的复选框，然后是去掉标记、字段与锚点的文字，再是块的字段 chip（状态字段带着它那一档的图形——只画这一处，在 chip 上；其余是 `key: value`）、标签——查询 `tag:` 已经指定的那个除外，每行重复它没有意义——任务的日期，以及笔记标题。正文只剩标签和字段的块（一行 `#chapter [status:: unread]` 的标记行）用笔记标题做文字。当结果带有状态字段时，表头统计各档的数量，并把已完成与进行中的份额画成一条进度条。行上的复选框和字段 chip 是活的：点任务的复选框切换完成（⌥ 切换进行中），点 chip 打开与编辑器相同的取值菜单，选中的值写进块所在的笔记——这是查询块唯一会做的写入，每一次都来自一次点击。

**降级**：**普通代码块**，原样显示查询条件。这是有意设计——查询结果是派生数据，永远不写进磁盘，所以外部工具看到的和磁盘上的完全一致。

## 可运行代码块

` ```js ` / ` ```javascript ` 代码块（语言标注大小写不敏感）在编辑器里带一个「运行」按钮，点击把块内容送进 Rust 侧的一次性只读沙箱（2 秒熔断、无写 API、无网络），输出渲染在闭合围栏之后，只存在于编辑器状态，**永不落盘**，关掉文档即消失。

**永不自动执行**：打开笔记 ≠ 运行代码；整条链路唯一入口是这个按钮，AI 也没有任何执行代码的工具。

### 实验块

调用了 `vemry.lab.*` 的代码块是一个**实验**：它声明控件、读取控件的值、画出视图。读者看到的是卡片，不是代码：光标在围栏之外时整个块被替换成它的卡片——第一次运行前是一行冷卡（块首行的 `//` 注释作说明，加一个「运行」按钮），运行后是实时卡片，带它声明的控件和画出的视图。卡片开着的时候，拖动控件就用控件当前的值重跑这个块（同一个沙箱、同一条熔断、一次拖动一次运行）。代码只在点卡片上的 ✎ 或把光标放进围栏时才显示；显示代码时不显示卡片（与查询块一致），光标离开后卡片回来，控件停在原处。运行后又改过的块会在卡片上说明并等待再次运行。关掉卡片（✕）回到冷卡；关掉文档实验结束，下次打开看到的又是冷卡。上面那条规则一点没松：第一次运行仍然是那一下点击，重跑只会跟在人的动作之后。

```js
const { d_k, scale } = vemry.lab.controls({
  d_k:   { slider: [4, 512], step: 4, value: 64, label: "d_k" },
  scale: { toggle: true, label: "除以 √d_k" },
  head:  { select: ["head 1", "head 2"] },
});
const Q = vemry.lab.matrix("Q", [[1, 0, 1], [0, 1, 0]]);   // 可编辑的数字网格
vemry.lab.heatmap("attention", weights, { rows: tokens, cols: tokens, digits: 2 });
vemry.lab.line("位置编码", [{ name: "dim 0", y: pe0 }, { name: "dim 1", y: pe1 }], { xLabel: "position" });
vemry.lab.bars("BLEU", { base: 27.3, big: 28.4 }, { yLabel: "BLEU" });
vemry.lab.scatter("参数量 vs BLEU", [[65e6, 27.3], [213e6, 28.4]], { xLabel: "params" });
vemry.lab.table("消融", [{ variant: "base", heads: 8, BLEU: 25.8 }], { highlight: { row: 0 } });
vemry.lab.step("softmax", [{ label: "分数", value: [[2, 0]] }, { label: "除以 $\sqrt{d_k}$", value: [[1, 0]] }]);
```

- **控件**（五种）：`slider: [min, max]` 配 `step` 与 `value`；`toggle: true|false`（这个布尔值就是默认值）；`select: [options]` 配 `value`；`matrix(name, rows, { label, min, max, step })`；`presets: [{ label, set: { name: value } }]`（或 `{ label: { name: value } }`）——一排按钮，每个一次设定其它若干控件，即卡片的引导实验（「所有 key 相等」「遮住未来」），其值是最后按下的那个标签。`controls` 返回当前值，`matrix` 返回当前网格。用户拖过的值在下一次运行时回来，并被钳在声明的范围内（形状不同的矩阵退回声明的那个）。
- **视图**（六种）：`heatmap(title, rows, { rows, cols, min, max, digits, diverging })`——单色由浅到深，数据有正有负时以零为中点两极着色；`line(title, series, { x, xLabel, yLabel, yMin, yMax })`，一条序列是 `y[]` 或 `{ name, y, x }`；`bars(title, data, { yLabel, horizontal })`，data 可以是 `{ label: value }`、`[[label, value]]` 或 `{ labels, series: [{ name, values }] }`；`scatter(title, points | [{ name, points }], { xLabel, yLabel })`；`table(title, rows, { columns, digits, highlight: { row, col } })`，行是数组或对象；`step(title, steps)`——逐步展开的推导，每步 `{ label, text, value }`（text 可含 `$…$`；value 是数、向量或网格）。
- 每张图都有表格孪生（卡片上的 ⊞ 按钮），每个标记都有悬停读数，两条及以上序列必有图例。颜色是主题固定的八个序列槽位，按序使用——上限是 8 条序列、64×64 热图格、每序列 2048 点、200 行表格、64 步、12 个控件、8 个视图；超过上限时块报出限制而不是画出来。
- **固定**（卡片上的图钉）把控件当前值写回代码里的字面量——`value: 64` 变成 `value: 128`，矩阵数组被重写——实验下次打开就停在读者离开的地方。这是实验唯一的一次写入，而且是显式的；拖动控件永远不碰笔记。

**降级**：普通 `js` 代码块，笔记里放的本来就是它。

## 隐私标记

四个彼此独立的入口。前三个把整个路径划进隐私区（永不读取、永不写入、永不进入提示词）；第四个对单个块做同样的事：

- 笔记 frontmatter 里的 `private: true`
- `.vemry/privacy` 里的一条 glob 规则（gitignore 语法，不分大小写）
- 任何以 `.` 开头的路径段（内置，无需配置）
- 一个 `> [!private]` callout——这个块会从 AI 读到的一切里被移除（笔记正文、搜索、块查询、引用、附上的选区），没有占位符；它所在的笔记也不能再被 AI 整篇覆盖（只能编辑）。它里面的 `#标签`、`[[链接]]` 与 `key:: value` 字段对任何人都不索引，所以不会经由标签统计、反链或图谱泄露。

**降级**：`private: true` 是普通的 frontmatter 键，`.vemry/privacy` 是普通文本文件。`> [!private]` 块是首行写着 `[!private]` 的普通引用块——**别的工具会显示它的内容**。隐私隔离是 vemry 的运行时行为，不改变文件本身。

## 新增语法的门槛

往这份方言里加东西之前，三条都要满足：

1. **写进本文**，连同它的降级形态一起；
2. **在不认识它的标准 Markdown 渲染器里优雅降级**——退化成可读的纯文本或标准结构即可，但不允许让内容消失、让后续结构错乱（例如吃掉整段、破坏列表或围栏嵌套）；
3. **不依赖边车文件还原语义**——把 vault 目录整个拷走、只用一个普通编辑器打开，写下的东西必须还在。

判据是可证伪的：拿一个纯 CommonMark 渲染器跑一遍，对照本文写明的降级形态。
